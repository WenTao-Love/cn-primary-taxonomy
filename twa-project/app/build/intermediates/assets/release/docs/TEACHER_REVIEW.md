## 二、核心教学场景需求对照

### 场景一：备课 📋

> **教师日常**：明天上三年级数学"分数的初步认识"，我要快速知道——这个知识点在教材第几页？第几单元？课标要求是什么？学生之前需要掌握什么前置知识？

| 需求 | 当前满足度 | 问题 |
|---|---|---|
| 教材定位（页码/单元） | ❌ **严重不足** | pageRange缺失94.8%，unit缺失47.8%，数学课本版本没有区分到具体页码 |
| 课标对照 | ⚠️ **部分满足** | 有191个课标编码，但只有编码没有课标原文。教师需要知道课标的具体表述 |
| 前置知识查询 | ✅ 满足 | 依赖图完整且reason字段的表述清晰 |
| 教学目标提炼 | ⚠️ **模板化严重** | evidence字段几乎一模一样："能较独立完成xxx相关任务"——不同知识点的掌握标准应该不同 |
| 教学流程建议 | ❌ **完全缺失** | practiceChain字段28.8%缺失；已有的也比较简略（如"跟读并指认"），缺少有操作性的步骤 |

### 场景二：命题出卷 📝

> **教师日常**：期末要出卷，我需要知道每个知识点怎么考、常考什么题型、学生最容易错在哪里。

| 需求 | 当前满足度 | 问题 |
|---|---|---|
| 考法提示 | ⚠️ **部分可用** | 语文/数学有95%+覆盖，但内容雷同（几乎都是"常考：选择题、填空题"，缺少区分度） |
| 易错点分析 | ⚠️ **能用但浅** | 存在率97.6%，但每点大多只有1条。如数学"小数乘法"仅标注"积的小位数数错"，而实际教学中还有"竖式对位错误""末尾0处理"等多种典型错法 |
| 题型示例 | ❌ **严重不足** | resources中的链接100%是Bing搜索聚合入口，实际不是"例题"。老师想要的是真正的典型题、变式题 |
| 变式题链 | ❌ **完全缺失** | 这是老师最需要的——给出基础题→变式题→拓展题的完整练习链 |

### 场景三：学情诊断 / 错题归因 🔍

> **教师日常**：学生分数除法做错了，我需要沿着前置链找到根本薄弱点。

| 需求 | 当前满足度 | 问题 |
|---|---|---|
| 错题归因路径 | ✅ **核心亮点** | DAG依赖图 + reason字段质量高（>30字的详细解释），"先学什么再学什么"逻辑清晰 |

## 三、逐字段教学质量深度剖析

### 3.1 evidence（掌握标准）——模板化最严重的问题

查看大量样本发现，evidence的内容几乎完全模板化：

```
典型 pattern：
- "能较稳定地完成'xxx'相关任务"
- "能在情境中较准确地使用xxx"
- "能较独立完成'xxx'相关任务"
- "能用自己的话说明'xxx'的核心意思"
```

**教师视角的问题**：不同学科、不同知识点的掌握标准应该有本质区别。比如：
- 数学"20以内进位加法" → 应该是"能正确计算，速度达到每分钟8题，正确率95%以上"
- 语文"看图写话" → 应该是"能用3-5句话把图上说清楚，句子通顺，标点基本正确"
- 英语"问候词汇" → 应该是"听到Hello能做出正确回应，看到图片能说出对应的词"

建议：按照布鲁姆认知层次（记忆/理解/应用/分析/评价/创造），为每个知识点的evidence设置差异化动词。

### 3.2 resources（资源链接）——当前是"假资源"

10341个资源链接，100%指向同一个模式：
```
https://www.bing.com/search?q=一年级+数学+典型例题+...
```

**教师视角**：这不是资源，这是搜索入口聚合页。一个老师点开链接后看到的是一堆广告和无关内容。

建议：资源可以分为两级：
1. **冷启动保留**：保留搜索入口作为兜底
2. **热替换**：逐步替换为真正的外部资源，如国家中小学智慧教育平台的对应课时、人教社微课本省、B站上的名师课视频片段（需授权）

### 3.3 cross-subject dependencies（跨学科依赖）——完全缺失

当前4191条依赖关系中，**跨学科依赖为0（0%）**。

**教师视角**：这是非常不符合教学实际的。比如：
- 数学"统计与概率" → 依赖语文"数据读取/文字理解"
- 科学"观察记录" → 依赖语文"观察日记/描述性表达"
- 数学"解决问题（应用题）" → 依赖语文"阅读理解"
- 英语"阅读" → 依赖语文"阅读策略"

即使作为弱依赖，也应该标注。

### 3.4 clusters（领域概览）——内容参差不齐

观察clusters.json发现，部分summary有实际内容（如科学"生命科学"提到了"蒙眼猜物"游戏），但大多数summary是模板化的填充文本："X学科·X领域：X年级低段将学习约XX个相关知识点，为后续中高段学习打基础。"

这种套话对老师毫无价值，应该写具体的"这一类知识的关键教学建议"。

## 五、最重要的问题排序（P0→P3）

### P0 — 不解决，项目无法进入一线教学场景

1. **教材页码定位缺失**：94.8%的话题没有页码。老师无法快速找到"这个知识点在课本上到底在哪里"。必须逐学科逐版本回填。
2. **资源链接无效**：Bing搜索入口不是资源。要么找真实资源（智慧教育平台），要么把资源模块改为"教师提示"而非链接。
3. **evidence模板化**：掌握标准需要差异化，不能用一套模板。这是整个知识库能否进入"教师备课+"场景的关键。
4. **缺乏教师端数据隔离**：家长端 / 教师端的掌握状态混存在同一个localStorage，教学场景完全不可用。

### P1 — 严重影响教学实用性

5. **跨学科依赖为0**：补充语文↔数学↔科学之间的弱依赖关系。
6. **练习系统题目太浅**：当前H5练习基于evidence字段自动生成，但evidence本身就是模板化的，所以题目几乎无区分度。需要引入真正的题库或升级出题逻辑。
7. **单元信息缺失**：47.8%的话题没有unit字段，无法按"第X单元"组织视图。
8. **examTips雷同**：语文/数学几乎全是"常考：选择题、填空题"，缺少区分度的考法分析。

### P2 — 影响完整性和扩展性

9. **课标编码需要原文对照**：有191条课标编码，但没有编码→原文的映射文件。老师不熟悉课标编码体系，需要看到原始表述。
10. **英语完全无examTips和skillRubric覆盖不统一**：英语224个话题中，0个有examTips；224个都有skillRubric（仅英语有）。其他学科应该有但缺失。
11. **缺乏"知识点↔试卷真题"关联**：老师需要看到"这个知识点在近5年区/市统考中怎么考的"。
12. **子节点类型（subnodeType）缺失**：数学787个（31.3%）、语文292个（25%）没有subnodeType。

### P3 — 锦上添花

13. **增加"教学重点/难点"独立字段**：目前混在description中。
14. **增加"易课时分配"建议**：如"建议1课时"。
15. **增加"教具/学具"建议**：如"需要计数器/小棒/数位顺序表"。
16. **增加"板书设计"参考图**。

## 六、与真实教学场景的Gap分析

### Gap 1：学校使用场景不可行

**问题**：当前系统假设"一个家长对孩子"，但学校场景是"一个老师对50个学生"。老师目前无法：
- 创建班级、导入学生名单
- 查看全班50人的掌握热力图
- 一键生成"全班学习路径"推荐
- 导出学情报告（周报/月报/学期报告）

**建议**：
- 短期：支持CSV导入学生名单 + 学情数据表（每行一个学生）
- 中期：构建教师仪表盘，展示班级整体掌握情况、全班共性薄弱点
- 长期：接入学校教务系统API，自动同步班级信息

### Gap 2：学期/教学进度视图缺失

**问题**：老师是按"第1周、第2周…"来安排教学进度的。当前系统按年级/学科组织，但看不到：
- 这学期应该教哪些知识点（按教材单元顺序）
- 教学进度到哪里了（哪些已教、哪些待教）
- 进度与掌握状态的对比（教了但学生没掌握的需要复习）

**建议**：增加"教学日历"视图，按周/次组织知识点，支持拖拽标记"已教/未教"。

### Gap 3：题库系统完全缺位

**问题**：当前没有真正的题库。老师需要为每节课准备作业，最花时间的就是选题。

**建议**：
- 为每个知识点建立3-5道分层次练习题（基础/提升/拓展）
- 支持按题型（填空/选择/判断/计算/操作/解决问题）筛选
- 支持一键导出Word版作业（不需排版）

### Gap 4：考试场景对接缺失

**问题**：
- 无法按"考试范围"生成
- 无法按"分值权重"区分重点
- 缺乏与真题的关联

## 八、真切话：优势与信心

作为一线教师，我必须说：

### 做得好的地方（值得骄傲的）

1. **DAG依赖图是整个项目的灵魂**——"先学什么后学什么"比"学什么"更重要，市面上几乎没有产品做到这个层次
2. **reason字段质量高**——4191条依赖全部有详细解释，且>30字，这是真正懂教学的人写的
3. **H5版的小伙伴模式**——星星奖励、正向激励，说明团队确实站在孩子角度思考了
4. **掌握状态追踪**——比很多商业化产品做得更细腻
5. **教材版本覆盖广**——统编版+北师大+苏教+人教+外研+译林，考虑了全国差异

### 信心

这个项目的骨架是对的，方向是对的。**知识图谱 + 依赖关系 + 学习路径**的方向，比市面上绝大多数"短视频+刷题"产品更接近教育本质。

当前最迫切的工作：**从"能看到"进化到"能用"，从"家长能用"进化到"老师能用"**。一旦跨过这个门槛，这个项目就不是"又一个知识图谱网站"，而是真正能进入学校、进入课堂的产品。

## 九、多角色版本拆分实施记录（2026年8月）

>  Ninth section: 回应本复盘报告"从家长能用进化到老师能用"的期望，项目实施了多角色版本拆分。

### 9.1 实施内容

按用户身份（家长/学生/教师）拆分HTML页面，实现高内聚、低耦合的前端架构：

| 角色 | 目录 | 主题 | 核心工具 |
|---|---|---|---|
| 家长 | `parent-web/` | 暗色主题 | 学习助手Bot、快速开始指引、小伙伴模式切换 |
| 学生 | `student-web/` | 明亮活泼主题 | 星星奖励、游戏化练习、正向激励 |
| 教师 | `teacher-web/` | 专业蓝色主题 | 课标对照、路径生成器、覆盖统计表、知识点库 |

### 9.2 架构改进

**拆分前**（问题）：
- 所有用户共用同一个 HTML 页面
- CSS/JS 逻辑混杂，排查困难
- 不同角色看到相同界面，体验无差异化
- 代码交接传承困难

**拆分后**（改进）：
- `shared/` 公共层：数据加载、索引构建、搜索、路径、存储、工具、D3图谱渲染
- 各角色页面只包含**专属** HTML/CSS/JS
- CSS Custom Properties (Design Tokens) 实现主题切换
- 分角色 localStorage 隔离（不同 key 前缀）
- data-loader 自动适配路径深度，无需手动配置

### 9.3 文件结构

```
cn-primary-taxonomy/
├── shared/                ← 公共层（所有角色共享）
│   ├── css/               ← tokens.css + common.css
│   ├── js/core/           ← 7个核心模块
│   └── js/graph/          ← D3图谱渲染引擎
├── parent-web/            ← 家长版
├── student-web/           ← 学生版
├── teacher-web/           ← 教师版
├── h5/                    ← H5移动版（也使用shared/模块）
└── build.mjs              ← 统一构建脚本
```

### 9.4 教师版专属功能实现

教师版（teacher-web/）专门回应了本复盘报告中提到的教学场景需求：

| 复盘发现 | 教师版实现 |

# CN-Primary-Taxonomy 团队 Skill 手册

## 1. 文档定位

本文件不是“项目规则”，而是“怎么做事”的操作手册。

适用对象：

- 新接手项目的同事
- 继续扩科、扩版本、补资源直链的开发者
- 负责图谱体验与性能优化的前端同学

## 2. 常见任务与推荐做法

## 2.1 扩一个新学科或新版本

推荐步骤：

1. 先明确是否属于主节点扩展、版本映射扩展、还是父子节点扩展
2. 先补生成脚本，再补 schema / validate
3. 再接入 `merge.mjs`
4. 再观察前端详情面板是否需要展示新字段
5. 最后更新 README / DESIGN / memory

不要直接在 `data/topics.json` 手改长期维护数据。

## 2.2 给数学补真实作品 ID 直链

推荐步骤：

1. 先确认目标是否真的是高频、高价值单元
2. 先检查现有资源是否还是 `unit-pack` 或聚合入口
3. 资源匹配必须至少限定到：
   - 学科
   - 教材版本
   - 年级
   - 节点名称
4. 若同名单元容易混淆，要再加上册次 / 单元语义约束
5. 新增 `externalWorkId` 后，重跑合并与校验

经验原则：

- 先补准，再补多
- 宁可保留映射位，也不要误挂直链

## 2.3 给非主科推广“父节点 + 子节点 + 练习链 + 评价框架”

推荐路径：

1. 先定义该学科的子节点类型
2. 再定义该学科的 `practiceChain`
3. 再定义 `assessmentTasks`
4. 最后落 `evaluationRubric`

建议优先保持和语文 / 科学 / 道法 / 劳动 / 体音美 / 信息科技现有模式一致。

## 2.4 优化图谱页面体验

优先级顺序：

1. 先消除遮挡
2. 再降低长挂负载
3. 再优化交互细节

当前推荐做法：

- 搜索、筛选、状态提示统一放到右侧边栏
- 年级 / 学科 / 版本统一用可搜索的多选下拉
- 图谱默认只画当前筛选子图
- 页面隐藏时销毁旧图，恢复时重建

## 2.5 处理"越挂越卡"

优先排查：

1. 是否存在旧 simulation 未释放
2. 是否存在 `tick` 持续写 DOM
3. 是否存在 `requestAnimationFrame` 未取消
4. 是否存在 zoom 事件重复绑定
5. 是否存在搜索、缩放、重绘未做防抖

## 2.6 教育管理者视角操作手册

> 本节专为教育管理者/教育局工作人员设计，介绍如何建设性使用知识图谱系统辅助管理决策

### 2.6.1 开展区域学情诊断

推荐步骤：

1. 收集学校使用数据（知识点掌握度、错题分布、学习路径完成率）
2. 利用图谱的"薄弱知识点"识别功能，输出区域薄弱点TOP20
3. 对比城乡、校际数据，定位均衡度短板
4. 生成《区域学科质量诊断报告》
5. 组织教研活动针对性改进

### 2.6.2 推进教材版本适配

推荐步骤：

1. 梳理区内学校使用的教材版本分布
2. 对照图谱现有版本覆盖情况（人教版/北师大/苏教/统编/外研/译林等）
3. 识别缺口版本（如西师版、冀教版、青岛版等）
4. 协调资源完成缺失版本的知识点映射
5. 组织对应版本教师验收适配准确性

### 2.6.3 建立质量监测体系

推荐步骤：

1. 定义区域质量监测指标（掌握率、优秀率、合格率、薄弱点改善率）
2. 配置数据采集机制（日报/周报/学期报）
3. 设置关键指标预警阈值
4. 建立"发现问题→分析归因→制定对策→跟踪改进"的闭环流程
5. 定期发布《区域教育质量监测报告》

### 2.6.4 组织教师培训

推荐步骤：

1. 区分四类培训对象：学科教师、信息技术教师、教研员、管理者
2. 开发分层培训材料（基础操作→深度应用→数据分析→管理决策）
3. 先行试点培养"种子教师"
4. 通过"种子教师→校本培训→全员覆盖"逐层推广
5. 建立常态化答疑与支持机制

### 2.6.5 保障数据安全合规

必做清单：

1. 编制并发布《隐私政策》《用户协议》
2. 建立数据分级分类制度
3. 确保学生数据本地存储、不上传云端（除非有明确授权）
4. 敏感报告输出前进行脱敏处理
5. 制定数据泄露应急预案

### 2.6.6 推进规模化推广

推荐路径：

```
准备期(1-3月) → 试点期(3-6月) → 扩展期(6-12月) → 常态化(12月+)
├─ 领导小组        ├─ 选定1-2校       ├─ 扩大至10-20校     ├─ 区域全覆盖
├─ 试点学校        ├─ 种子教师        ├─ 校本培训          ├─ 纳入云平台
├─ 合规文件        ├─ 数据收集        ├─ 迭代优化          ├─ 长效机制
└─ 培训材料        └─ 反馈优化        └─ 效果验证          └─ 经验输出
```

## 4. 高风险点清单

### 4.1 资源治理高风险

- 同名节点跨教材版本串挂
- 用宽松关键词把“圆”挂到“圆柱圆锥”
- 把聚合入口误写成精准直链

### 4.2 图谱性能高风险

- 把控件重新放回主画布浮层
- 恢复全量节点默认渲染
- 新增动画但没有销毁逻辑
- 新增缓存但没有失效机制

### 4.3 文档高风险

- 数据已经变了，README 还写旧数字
- 交互已经变了，DESIGN 还写旧布局
- 团队已经形成新约束，但 memory 没更新

### 4.4 教育管理者视角高风险

- **数据安全事件**：学生隐私数据泄露（法规风险+公信力风险）
- **区域不平等加剧**：城乡数字鸿沟导致图谱只惠及城市学校
- **内容错误误导教学**：知识点失误导致区域性的教学偏差
- **推广受阻**：教师抵触或技术门槛过高导致推广失败
- **政策合规缺失**：未完成备案或缺乏隐私政策即推广至学校
- **可持续性断裂**：资金/人员变动导致项目无以为继

### 4.5 构建与交付高风险

- **独立版本路径断链**：构建脚本生成的HTML引用了不存在的文件路径，导致用户双击白屏
- **CDN依赖失效**：网络环境受限时D3.js无法加载，图谱无法渲染
- **构建产物未验证**：构建后未自动检查引用完整性，问题直到用户反馈才被发现

## 6. 当前默认共识

- 体验优先于花哨
- 精准优先于覆盖
- 显式配置优先于隐式推断
- 结构复用优先于另起一套
- 任何会导致资源泄露、内存泄露、IO 泄露、CPU 常驻空转的实现，都不应进入长期方案

# CN-Primary-Taxonomy 项目规则

## 1. 文档目的

本文件是仓库级“硬约束”文档，用于约束后续开发、优化迭代、多人协作与项目交接。

它回答三件事：

1. 什么事情绝对不能做错
2. 什么事情每次改动都必须同步处理
3. 什么事情一旦偷懒，后面一定会反噬

## 2. 不可破坏的核心原则

### 2.1 图谱必须保持为 DAG

- 所有知识依赖必须保持有向无环图
- 新增或调整依赖后，必须运行 `node scripts/validate.mjs`
- 不允许为了“看起来更完整”而引入循环依赖

### 2.2 资源挂接必须严防串挂和泄露

- 资源匹配口径至少要限定到：`学科 + 教材版本 + 年级 + 节点名称`
- 同名节点跨教材版本时，禁止复用宽匹配逻辑
- 外部资源若未确认准确性，不得伪装成“已精确直链”
- `externalWorkId`、`resourceId`、`resourceGroupKey`、`resourceUnitKey` 应优先显式维护，避免隐式推断失真

### 2.3 前端不得以“能跑”为标准

- 图谱页面要同时追求：可看、可筛、可长时间挂页、不卡顿
- 一切会遮挡主图谱的交互控件，默认应放入右侧边栏
- 一切长时间驻留的 D3/SVG/定时器/事件监听，都必须有明确的销毁路径

## 3. 性能与泄露防线

## 3.1 内存泄露防线

- `simulation.stop()` 不是终点，必须同时解除 `tick` 绑定并释放实例引用
- 页面隐藏、切页、卸载时，要主动清理：
  - force simulation
  - `requestAnimationFrame`
  - `setTimeout` / `setInterval`
  - zoom 命名空间事件
  - 旧图层节点引用

## 3.2 CPU 负载防线

- 默认只渲染当前筛选子图，不允许默认全量暴力渲染
- 拖拽结束后应自动停止布局
- tick 更新应通过 `requestAnimationFrame` 节流
- 搜索、缩放、重绘等高频动作应做防抖或节流

## 3.3 IO 负载防线

- 数据构建链路以静态 JSON 产物为主，避免页面运行期重复请求
- 单文件离线页优先采用 JSON 文本注入，避免超大 JS 对象字面量带来的解析负担
- 长时浏览优先提供拆分版离线页，降低单次加载压力

## 4. 数据与 Schema 约束

- 所有新增字段必须先补 `schema/topics.schema.json`
- 所有新增字段必须补 `scripts/validate.mjs`
- 父子节点扩展必须保证：
  - `parentTopicId` 指向合法
  - `subnodeType` 语义明确
  - 子节点不会误参与顶层自动依赖推断

## 5. 文档同步规则

凡是出现以下任一变更，必须同步更新文档：

- 学科范围变化
- 版本覆盖变化
- 节点总数或依赖总数变化
- 新增数据字段
- 新增构建脚本
- 前端交互方式变化
- 资源治理口径变化
- 性能治理策略变化

至少同步这些文件：

- `README.md`
- `docs/DESIGN.md`
- 本文件
- 相关 memory 文档

## 6. 团队协作规则

### 6.1 改数据，先想口径

- 不要先批量生成，再事后找补解释
- 先明确：
  - 本次改的是主节点、子节点还是资源层
  - 口径是教材目录映射、教学任务映射，还是评价框架映射
  - 会不会影响已有依赖或资源挂接

### 6.2 改体验，先想遮挡和常驻负载

- 任何新控件，先问自己会不会遮挡主图
- 任何新动画，先问自己会不会越挂越卡
- 任何新缓存，先问自己有没有释放路径

### 6.3 改资源，先想误挂

- 同名主题是本项目资源治理里的高危点
- 资源宁可少挂、慢挂，也不要错挂
- 外部直链若无法确保命中，应保留为映射位并显式标注，而不是伪装成精准资源

## 7. 交付前检查清单

每次提交较大改动前，至少确认：

1. `node scripts/merge.mjs`
2. `node scripts/generate-dependencies.mjs`
3. `node scripts/generate-manifest.mjs`
4. `node scripts/validate.mjs`
5. `node build.mjs --standalone`（构建所有角色独立版本）
6. `node scripts/build-standalone.mjs`
7. `node scripts/build-split-standalone.mjs`
8. `node scripts/validate-build.mjs`（验证所有构建产物路径完整性）
9. README / DESIGN / 规则文档是否同步
10. 页面是否存在控件遮挡主图
11. 长挂页面的定时器、simulation、zoom 事件是否有回收路径

## 8. 教育管理者视角专项规则

> 本节规则专为教育管理者/教育局视角设计，涉及政策合规、数据安全、区域适配、质量管控等维度的约束

### 8.1 政策合规红线

- **必须对齐国家课标**：所有知识点映射必须基于《义务教育课程标准（2022年版）》，不得偏离
- **双减政策合规**：不得增加学生额外负担，不得变相推广校外培训
- **数据本地化优先**：学生学习数据应坚持"本地存储优先"原则，未经家长明确授权不得上传云端
- **教育APP备案**：一旦推广至学校应用，须完成教育移动互联网应用程序备案
- **未成年人保护**：涉及未成年人数据须符合《未成年人网络保护条例》

### 8.2 数据安全与隐私保护

- **隐私政策必备**：任何面向用户的入口均需配备《隐私政策》《用户协议》
- **最小必要原则**：仅收集实现功能所需的最少个人信息
- **数据分级分类**：建立数据分级制度，明确公开数据、内部数据、敏感数据的边界
- **匿名化处理**：区域质量分析报告须对学生个人身份信息进行匿名化处理
- **访问权限控制**：教育管理者视图的访问须配备权限控制机制，防止数据泄露
- **日志审计**：管理后台操作须留有审计日志

### 8.3 区域适配规则

- **教材版本中立**：不得仅支持单一教材版本，主流版本须提供平等支持
- **城乡差异适配**：必须提供离线版/低带宽版，保障农村和薄弱学校可用
- **多语言支持**：民族地区应考虑提供双语或多语言界面支持
- **无障碍访问**：应遵循WCAG 2.1 AA级标准，保障残障人士可用

### 8.4 质量管控规则

- **专家审核机制**：新增学科/知识点须经过"学科专家→教研员→一线教师"三级审核
- **校对反馈入口**：页面须提供知识点错误反馈入口，明确反馈处理时限（建议≤7工作日）
- **时效性校验**：每学期至少进行一次课标/教材同步性审查
- **准确性指标**：知识点准确率目标≥99%，依赖关系准确率目标≥98%
- **第三方评估**：重大更新发布前建议邀请第三方机构进行内容评估

### 8.5 规模化推广规则

- **分层培训体系**：须配套教师培训材料，区分学科教师/信息技术教师/教研员/管理者四类培训
- **可观测性**：须配备使用数据采集能力，为推广效果评估提供依据
- **灰度发布机制**：推广前须经过试点→扩展→常态化的分阶段验证
- **退出机制**：须为不使用该工具的学校/教师提供不影响正常教学的退出路径

### 8.6 督导评估能力

- **薄弱点识别**：须能输出"区域薄弱知识点TOP20"等决策支持数据
- **均衡度指标**：须能提供城乡、校际、学科间的均衡度对比数据
- **趋势分析**：须支持知识点掌握率的时间序列分析（至少支持学期维度）
- **预警机制**：关键指标异常时须能触发预警提示

### 8.7 可持续发展保障

- **开源协议合规**：明确开源协议的法律适用性，保障各方权益
- **社区健康度**：建立贡献者行为准则，保障社区积极健康发展
- **资金透明度**：若接受政府/社会资助，须定期公开资金使用报告
- **应急预案**：须制定数据安全事件、内容争议等突发情况的应急处置预案

## 9. 当前特别提醒

- 右侧边栏是当前统一交互入口，新增筛选、搜索、状态类控件时请延续这一布局
- 数学资源治理当前处于"映射位 -> 外部作品 ID 直链"过渡阶段，新增直链时必须优先保证准确性
- 多学科子节点与评价框架已成项目固定模式，后续扩展应尽量复用现有字段和渲染方式，避免再造一套并行结构
- 本次新增教育管理者视角，若后续开发涉及区域对比、质量监测、数据安全等功能，须优先遵守第8章专项规则

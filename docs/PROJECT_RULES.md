# CN-Primary-Taxonomy 项目规则

## 1. 文档目的

本文件是仓库级“硬约束”文档，用于约束后续开发、优化迭代、多人协作与项目交接。

它回答三件事：

1. 什么事情绝对不能做错
2. 什么事情每次改动都必须同步处理
3. 什么事情一旦偷懒，后面一定会反噬

## 2. 不可破坏的核心原则

### 2.1 图谱必须保持为 DAG

- 所有知识依赖必须保持有向无环图
- 新增或调整依赖后，必须运行 `node scripts/validate.mjs`
- 不允许为了“看起来更完整”而引入循环依赖

### 2.2 资源挂接必须严防串挂和泄露

- 资源匹配口径至少要限定到：`学科 + 教材版本 + 年级 + 节点名称`
- 同名节点跨教材版本时，禁止复用宽匹配逻辑
- 外部资源若未确认准确性，不得伪装成“已精确直链”
- `externalWorkId`、`resourceId`、`resourceGroupKey`、`resourceUnitKey` 应优先显式维护，避免隐式推断失真

### 2.3 前端不得以“能跑”为标准

- 图谱页面要同时追求：可看、可筛、可长时间挂页、不卡顿
- 一切会遮挡主图谱的交互控件，默认应放入右侧边栏
- 一切长时间驻留的 D3/SVG/定时器/事件监听，都必须有明确的销毁路径

## 3. 性能与泄露防线

## 3.1 内存泄露防线

- `simulation.stop()` 不是终点，必须同时解除 `tick` 绑定并释放实例引用
- 页面隐藏、切页、卸载时，要主动清理：
  - force simulation
  - `requestAnimationFrame`
  - `setTimeout` / `setInterval`
  - zoom 命名空间事件
  - 旧图层节点引用

## 3.2 CPU 负载防线

- 默认只渲染当前筛选子图，不允许默认全量暴力渲染
- 拖拽结束后应自动停止布局
- tick 更新应通过 `requestAnimationFrame` 节流
- 搜索、缩放、重绘等高频动作应做防抖或节流

## 3.3 IO 负载防线

- 数据构建链路以静态 JSON 产物为主，避免页面运行期重复请求
- 单文件离线页优先采用 JSON 文本注入，避免超大 JS 对象字面量带来的解析负担
- 长时浏览优先提供拆分版离线页，降低单次加载压力

## 4. 数据与 Schema 约束

- 所有新增字段必须先补 `schema/topics.schema.json`
- 所有新增字段必须补 `scripts/validate.mjs`
- 父子节点扩展必须保证：
  - `parentTopicId` 指向合法
  - `subnodeType` 语义明确
  - 子节点不会误参与顶层自动依赖推断

## 5. 文档同步规则

凡是出现以下任一变更，必须同步更新文档：

- 学科范围变化
- 版本覆盖变化
- 节点总数或依赖总数变化
- 新增数据字段
- 新增构建脚本
- 前端交互方式变化
- 资源治理口径变化
- 性能治理策略变化

至少同步这些文件：

- `README.md`
- `docs/DESIGN.md`
- 本文件
- 相关 memory 文档

## 6. 团队协作规则

### 6.1 改数据，先想口径

- 不要先批量生成，再事后找补解释
- 先明确：
  - 本次改的是主节点、子节点还是资源层
  - 口径是教材目录映射、教学任务映射，还是评价框架映射
  - 会不会影响已有依赖或资源挂接

### 6.2 改体验，先想遮挡和常驻负载

- 任何新控件，先问自己会不会遮挡主图
- 任何新动画，先问自己会不会越挂越卡
- 任何新缓存，先问自己有没有释放路径

### 6.3 改资源，先想误挂

- 同名主题是本项目资源治理里的高危点
- 资源宁可少挂、慢挂，也不要错挂
- 外部直链若无法确保命中，应保留为映射位并显式标注，而不是伪装成精准资源

## 7. 交付前检查清单

每次提交较大改动前，至少确认：

1. `node scripts/merge.mjs`
2. `node scripts/generate-dependencies.mjs`
3. `node scripts/generate-manifest.mjs`
4. `node scripts/validate.mjs`
5. `node scripts/build-standalone.mjs`
6. `node scripts/build-split-standalone.mjs`
7. README / DESIGN / 规则文档是否同步
8. 页面是否存在控件遮挡主图
9. 长挂页面的定时器、simulation、zoom 事件是否有回收路径

## 8. 当前特别提醒

- 右侧边栏是当前统一交互入口，新增筛选、搜索、状态类控件时请延续这一布局
- 数学资源治理当前处于“映射位 -> 外部作品 ID 直链”过渡阶段，新增直链时必须优先保证准确性
- 多学科子节点与评价框架已成项目固定模式，后续扩展应尽量复用现有字段和渲染方式，避免再造一套并行结构

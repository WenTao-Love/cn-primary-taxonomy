## 三、代码架构与可维护性审计

### 3.1 架构优势 ✅

| 优势 | 说明 |
|------|------|
| 共享模块设计 | tokens.css + common.css + 8个core JS + 6个组件 |
| 多策略数据加载 | 嵌入式→JS文件→JSON fetch 自适应 |
| CSS变量系统 | 17个学科色+功能色+间距+圆角+阴影+过渡 |
| 角色主题隔离 | 15个角色各有独立CSS，通过body class区分 |
| 零外部依赖 | D3.js本地vendor化，可完全离线运行 |

### 3.2 代码冗余问题 ⚠️

| 重复项 | 涉及文件 | 行数 | 严重度 |
|--------|----------|------|--------|
| `showNodeDetail()` | parent/teacher/h5 (3文件) | ~270行 | 🔴 极高 |
| `showLoadError()` | parent/student/teacher/h5 (4文件) | ~60行 | 🟠 高 |
| `init()` 引导序列 | 全部4文件 | ~80行 | 🟠 高 |
| `generateQuestions()` + 练习渲染 | student/h5 (2文件) | ~100行 | 🟠 高 |
| `showMascotTip()` + `showEncourage()` | parent/student (2文件) | ~20行 | 🟡 中 |
| `updateStats()` | student/h5 (2文件) | ~15行 | 🟡 中 |
| 学习路径渲染 | student/h5 (2文件) | ~40行 | 🟡 中 |
| Tag构建 | parent/teacher/h5 (3文件) | ~15行 | 🟡 中 |
| 掌握度按钮行 | parent/student/h5 (3文件) | ~20行 | 🟡 中 |

**预估影响**：
- 总重复代码：~400-500行
- 抽取后预计保留：~150-200行（角色配置+调用）
- 净减少：~250-300行重复代码

### 3.3 事件监听器管理 ⚠️

| 指标 | 数值 | 风险 |
|------|------|------|
| `addEventListener` 调用 | 102 | 中 |
| `removeEventListener` 调用 | 2 | 高 |
| 比率 | 51:1 | 🔴 |

> **风险**：单页应用中DOM元素被销毁重建时，旧监听器可能无法回收，导致内存泄漏。

### 3.4 架构改进建议

```
P1（短期）
├── 抽取 showNodeDetail() 为共享组件（减少150行重复）
├── 抽取 showLoadError() 为共享组件（已部分完成）
├── 引入事件委托替代部分addEventListener
└── 统一init()引导序列为可配置模板

P2（中期）
├── 练习系统组件化（student/h5共享）
├── 学习路径渲染组件化
├── 掌握度管理组件化
└── 建立组件文档和API规范
```

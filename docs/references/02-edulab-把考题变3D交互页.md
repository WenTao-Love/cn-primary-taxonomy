大家好，我是兔仙人。今天继续看 GitHub。

给家里的中学生讲一道立体几何题，最费劲的不是他不会算，是他在纸上想象不出那条线和那个面到底什么关系。你画了半小时，他点头说明白了，第二天考试还是错。

现在有人说，把题目丢给 AI，它直接给你生成一个能转能拖的 3D 页面，旁边配分步解析。

听着挺美。问题是，AI 给你画出来的那张图，答案可能是错的。

而且它错得很体面——动画流畅，配色好看，公式排得整整齐齐，你根本看不出那个数是编的。

01CHAPTER

它把“算”和“画”切成了两件事




GitHub 上这个叫 edulab 的项目，思路和大多数 AI 解题工具不一样。

它不让大模型算题。

题目进来，先归一成一份结构化描述，再交给 sympy——一个专门做符号计算的老牌 Python 库，算出精确坐标、法向量、最终答案。每一步的中间量都是分数和根号的精确形式，不是小数近似。

算完之后，这些数被注进前端模板。3D 顶点坐标直接由计算结果给出。

说白了，画面上那个点在哪，就是算出来的那个点在哪。 不是“看起来像个立方体”，是真按坐标摆的。

这个设计解决的是 AI 解题最要命的问题：计算可以复核，画面不会自己编。

一个参数滑杆能拖动，靠的不是动画，是背后的解析解。

它有三种入口：直接给文字题目、上传题目图片、随机出题。

图片入口有个细节我挺在意——它识别完之后会把题面回显给你确认，确认了才继续解。这说明作者清楚视觉识别会读错。

随机出题也一样，参数随机之后答案不规整就重抽。要的是“能当例题”的题，不是“能跑通”的题。

02CHAPTER

我拿它跑了三道题




光看 README 说明不了什么，我直接跑了。

先说结论：三个交互页全部跑通，只装了 sympy，没装任何 Agent。

三道题，三个自包含的 html 文件，每个 50KB 左右，双击就能打开，断网也能看——3D 库和公式库都内嵌在里面。

第一道，正方体线面角。正方体 ABCD–A₁B₁C₁D₁ 棱长 1，求直线 A₁C 与底面 ABCD 所成角的正弦值。

生成出来的页面，左边是题面、最终答案 √3/3、四步解析。第一步“建立空间直角坐标系”，直接把 A(0,0,0)、C(1,1,0)、A₁(0,0,1) 列出来。

右边是能拖能转的 3D 立方体，八个顶点都标了名字。

这里要说清楚一点：初始只显示立方体本身，那条 A₁C 和底面的高亮，要点“下一步”才出来。是分步展示，不是一次全糊在屏幕上。

第二道，椭圆里动向量数量积的范围。椭圆离心率 1/2 过点 P，M(−1,0)，过右焦点 F 的直线 l 交 C 于 A、B，求 MA·MB 的取值范围。

这个页面信息密度最高。左边题面下面一排滑杆，拖“旋转倾斜角 θ”，右边画板上的直线跟着转。A、B 两个交点、两条向量、数量积的实时读数全部同步变。

中间是三步骤详细解析，公式用 KaTeX 排的，标准方程、联立韦达、数量积化简，一步不缺。

页面初始是 45 度，屏幕上读到 −0.286，理论范围写着 [−3, 7/4]。

这里有个我没想到的细节：这道题的答案是闭区间。端点能不能取到，靠“有没有真实直线能取到”来判断，不是拍脑袋写个开区间。

所以答案框里的范围和滑杆能拖到的值始终对得上——我把 θ 一路拖到 0 度，数量积的读数变成 −3.000，正好卡在理论范围的下端。这一帧里直线就是 x 轴，A(−2,0)、B(2,0)，谁都能拿手算复核一遍。

这种一致性，比“答案对不对”更难做到。

第三道，甲烷燃烧。左边是 3D 球棍模型的甲烷和两个氧气分子，拖“反应进度”滑杆，看化学键断开、原子重新组合。

右边方程式 CH₄ + 2O₂ --点燃--> CO₂ + 2H₂O，三个步骤条：反应物混合、点燃燃烧、生成产物。下面是原子守恒计数，C×1、O×4、H×4，反应前后不变。

配平不是查表查出来的，是由元素矩阵零空间求整数计量数算出来的。原子守恒是真的数出来的，不是标上去的。

03CHAPTER

硬伤




第一，视频类是另一个世界。

交互页只要 Python 3 + sympy，装完敲一条命令就出页面。但数学、物理、化学那三个视频技能，要 Node 18+、playwright、ffmpeg-static、Chrome，还得在 lesson 目录里单独 npm install 一次。

我照它的脚本跑，环境检查直接报三项缺失：Python 的 numpy/requests/pypinyin/pillow、node 的 playwright、ffmpeg-static。

第二，视频必须有你自己的配音 key。

GLM-TTS、豆包、MiniMax 三选一，写在 .env 里。没有 key 它不会偷偷换成免费音色，会先停下来问你。

免费兜底只有 edge-tts（要联网）和 macOS 的 say（离线，机械感明显）。指南上写得很直白：效果较差。

这个做法是对的，不骗你，但也意味着你得先去弄一个 key 才能出片。

第三，题型就这六类。

立体几何、解析几何（圆锥曲线）、化学反应，加数学、物理、化学讲解视频。超出这六类，它不保证。

第四，它不替你出题。

你给题目，它解题。不是它出卷子给你做，也不是它替你讲课。README 里写得很清楚：“想要完全 AI 自动出题 + 自动教学的”不适合。

第五，没有网页界面。

装完是给 Agent 用的技能，或者你自己在命令行敲。想拿给不会配环境的人用，得自己想办法。

还有一条要说全：图片读题依赖 Agent 的视觉能力。模型看错题，后面算得再准也是错的——所以它才要你回显确认。

写在最后




这个项目最值得看的地方，不是那 6 个技能，是它把“算”和“画”分开的做法。

现在大部分 AI 教学工具，是让大模型一路生成到底——解题、画图、配音全交给一个模型。快是快，但你没法验证中间任何一步。

edulab 反过来：能用确定性方法算的，一律不交给模型。模型只负责把算好的结果，变成人看得懂的东西。

这个思路放到别的领域也一样成立。凡是“答案必须对”的场景，计算和表达就该切开。

到最后你会发现，判断一个 AI 工具靠不靠谱，有个很土的办法：它敢不敢让你复核中间过程。
